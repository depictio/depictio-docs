    Demultiplexing QC

    Sequencing-facility run sign-off: CheckQC verdicts, run health per lane and read, demultiplexing balance, undetermined reads and index swaps, and per-library read QC, next to the pipeline's own MultiQC report.

    nf-co.re GitHub

    Draft
    Template version latest

    The demultiplex template reads an nf-core/demultiplex run in the order a sequencing facility signs a run off:

    • MultiQC: what CheckQC flagged, then the Falco and fastp read QC of the demultiplexed FASTQ files
    • Run health: whether the instrument delivered, per lane, per read and per cycle
    • Demultiplexing: how evenly the reads of each lane were shared between the libraries
    • Undetermined and index swaps: what no index matched, and whether it is a swap between indexes in use
    • Library QC: how each library looks once demultiplexed, and whether the design groups differ

    Run at a glance (libraries, total yield, lowest-lane Q30, highest-lane Undetermined share) and the collapsed Sample sheet are pinned to the top of every tab, the Lane table to the bottom, and the Library filters group (library, design group, lane) applies everywhere.

    bcl2fastq by default, BCL Convert on request

    The two demultiplexers write different reports: bcl2fastq a Stats/Stats.json, BCL Convert Reports/Demultiplex_Stats.csv, Quality_Metrics.csv and Top_Unknown_Barcodes.csv. The template reads bcl2fastq by default; --var IS_BCLCONVERT=true repoints the same four collections at BCL Convert recipes that write the same columns, so every tile renders unchanged. BCL Convert reports no raw cluster count, so the pass-filter rate stays empty on that route.

    Lanes and reads are rows, design comes from a file

    Every run-level collection is one row per lane (and per read), so a one-lane benchtop run and a multi-lane production flowcell ingest through the same template. Design factors are never parsed out of library names: they come from an optional METADATA_FILE, and without it every library falls in a single group and every tile still renders.

    Quick start¶

    depictio ingest /path/to/demultiplex_results \
  --template nf-core/demultiplex/latest

    The results directory is the only thing you have to pass. To group libraries by a design factor, add a metadata TSV whose first column is the library name as written in the sample sheet:

    depictio ingest /path/to/demultiplex_results \
  --template nf-core/demultiplex/latest \
  --var METADATA_FILE=/path/to/library_metadata.tsv \
  --var GROUP_COL=organism

    depictio config nextflow --install     # once per machine
nextflow run nf-core/demultiplex -r 1.8.0 -profile docker --outdir results

    No depictio ingest, and no template named: the pipeline ingests its own output directory when it finishes and resolves this template from its own manifest. See Nextflow trigger.

    Reference¶

    The template reads the MultiQC report, the demultiplexer statistics of every flowcell and lane, the CheckQC report, the fastp JSON of every library and, when present, an Illumina InterOp summary table. A pipeline-local libraries recipe joins them into one row per library, the hub of the library filters. 48 of its 79 components carry a use: catalog reference, so a tile says where its panel comes from.

    Self-adapting layout

    The dashboard adapts to whatever the run actually produced: components bound to pruned or unparsed data collections are hidden, tabs left with no real visualizations are dropped entirely, and the remaining components are re-packed so there are no empty rows.

    Template variables¶

    Variables you provide when running the template: DATA_ROOT is the results directory given to depictio ingest, the others are set with --var NAME=value:

    Variable Required Description
    DATA_ROOT ✓ Root directory of one nf-core/demultiplex run (the flowcell folders, multiqc/, pipeline_info/)
    METADATA_FILE — Optional library metadata TSV. First column: the library name as written in the sample sheet; every other column (organism, input amount, project, ...) becomes a design column of the library hub.
    METADATA_ID_COL — Metadata library-name column. Auto-detected as the first metadata column; defaults to 'sample'.
    GROUP_COL — Metadata column the dashboards group and colour libraries by. Auto-detected as the first annotation column of METADATA_FILE; without metadata it falls back to a single group.
    IS_BCLCONVERT — Set (--var IS_BCLCONVERT=true) for a run demultiplexed with --demultiplexer bclconvert: the run-level collections read the BCL Convert Reports/*.csv instead of the bcl2fastq Stats.json. Matches the run's params.json demultiplexer.

    Auto-detected (set from the run's metadata / params.json; the route flags drive Conditional routes below): GROUP_COL_DISPLAY

    Data collections¶

    18 data collections — 5 required 13 optional · 9 direct 9 derived.

    Origin tells you whether a collection is real pipeline data or a reshape of it: direct = a pipeline output (scanned, or a recipe that reads raw files); derived = a recipe that reshapes one or more direct collections into the layout a visualization needs (no new measurement). Reads shows what produces it: a recipe .py transform, whose name links to its source on GitHub, or a raw file scanned off disk. (A direct collection can still have a recipe — one that merely parses/cleans the raw file; derived means the recipe reshapes another collection.)

    Tag Origin Type Reads Status

    metadata direct Table file {METADATA_FILE} optional
    bcl2fastq_stats_raw direct Table file Stats.json$ optional
    bclconvert_demux_raw direct Table file Demultiplex_Stats.csv$ optional
    bclconvert_quality_raw direct Table file Quality_Metrics.csv$ optional
    bclconvert_unknown_raw direct Table file Top_Unknown_Barcodes.csv$ optional
    demux_stats derived Table recipe bcl2fastq/demux_stats.py required
    lane_summary derived Table recipe bcl2fastq/lane_summary.py required
    read_quality derived Table recipe bcl2fastq/read_quality.py required
    unknown_barcodes derived Table recipe bcl2fastq/unknown_barcodes.py optional
    interop_summary_raw direct Table file .interop_summary..csv$ optional

    Recipes¶

    Each recipe reshapes raw pipeline output into a tidy table. The name links to its source; Output lists the validated OUTPUT_SCHEMA columns.

    Recipe Transforms Output
    bcl2fastq/demux_stats.py Reads per library and lane, with the undetermined reads, from bcl2fastq Stats.json. flowcell, lane, lane_label, sample, index, is_undetermined, level, reads, pct_of_lane, yield_mb, pct_q30, mean_quality, pct_perfect_index, pct_one_mismatch_index
    bcl2fastq/lane_summary.py Run health per lane from bcl2fastq Stats.json: clusters, yield, quality, balance. flowcell, lane, lane_label, clusters_raw, clusters_pf, pct_pf, yield_gb, pct_q30, mean_quality, n_libraries, library_reads, undetermined_reads, pct_undetermined, library_reads_cv, lowest_library_pct_of_mean
    bcl2fastq/read_quality.py Base quality per lane and read from bcl2fastq Stats.json. flowcell, lane, lane_label, read, read_label, yield_gb, pct_q30, frac_q30, mean_quality
    bcl2fastq/unknown_barcodes.py Top unknown barcodes per lane, classed as likely index swaps, from bcl2fastq Stats.json. flowcell, lane, lane_label, barcode, index1, index2, reads, rank, pct_of_lane, pct_of_undetermined, i7_in_use, i5_in_use, swap_class
    bclconvert/demux_stats.py Reads per library and lane, with the undetermined reads, from BCL Convert reports. flowcell, lane, lane_label, sample, index, is_undetermined, level, reads, pct_of_lane, yield_mb, pct_q30, mean_quality, pct_perfect_index, pct_one_mismatch_index
    bclconvert/lane_summary.py Run health per lane from BCL Convert reports: reads, yield, quality, balance. flowcell, lane, lane_label, clusters_raw, clusters_pf, pct_pf, yield_gb, pct_q30, mean_quality, n_libraries, library_reads, undetermined_reads, pct_undetermined, library_reads_cv, lowest_library_pct_of_mean
    bclconvert/read_quality.py Base quality per lane and read from BCL Convert Reports/Quality_Metrics.csv. flowcell, lane, lane_label, read, read_label, yield_gb, pct_q30, frac_q30, mean_quality
    bclconvert/unknown_barcodes.py Top unknown barcodes per lane, classed as likely index swaps, from BCL Convert reports. flowcell, lane, lane_label, barcode, index1, index2, reads, rank, pct_of_lane, pct_of_undetermined, i7_in_use, i5_in_use, swap_class
    interop/summary.py Run metrics per lane and read from interop_summary --csv=1: SAV's summary table. run_id, lane, lane_label, read, read_label, is_index_read, tiles, density_k_mm2, pct_cluster_pf, pct_cluster_pf_sd, phasing, prephasing, reads_m, reads_pf_m, pct_q30, frac_q30, yield_gb, pct_aligned, error_rate, error_rate_sd
    nf-core/demultiplex/checkqc_verdicts.py CheckQC verdicts per lane: which run-level thresholds the run failed, and by how much. report, handler, severity, lane, sample, index, value, threshold, message, instrument
    nf-core/demultiplex/cycle_quality.py Mean base quality per sequencing cycle, per lane and read, pooled over libraries. series, lane, lane_label, read, cycle, median_quality, p10_quality, p90_quality, n_libraries
    nf-core/demultiplex/fastp_library_qc.py Per-library read QC after demultiplexing, from the fastp JSON reports. sample, lane, lane_label, fastq_id, reads_before, reads_after, pct_passed, pct_low_quality, pct_too_many_n, pct_too_short, pct_duplication, pct_adapter_trimmed, gc_pct, pct_q30_before, pct_q30_after, mean_length_after, insert_size_peak
    nf-core/demultiplex/libraries.py The library hub: one row per demultiplexed library, the key every tab filters on. sample, flowcell, lanes, n_lanes, index, fastq_id, reads, pct_of_run, pct_of_expected, yield_mb, pct_q30, mean_quality, pct_perfect_index, reads_after_filter, pct_passed, pct_duplication, pct_adapter_trimmed, gc_pct, pct_q30_after, insert_size_peak

    Dashboard tabs¶

    Five tabs, read as a funnel: what the checks flagged, whether the instrument delivered, how the reads were shared, what went to Undetermined, and how each library looks. Each tab below carries the same icon and colour the dashboard gives it. The screenshots come from the run described under Validation runs below.

    What did CheckQC flag, and how do the demultiplexed FASTQ files look?

    The tab opens on the CheckQC verdicts: libraries under the read threshold, the Undetermined share against its limit, and the general statistics. Falco and fastp follow with reads per FASTQ file, per-read quality, adapter content and insert sizes. The remaining Falco and fastp panels are collapsed underneath.

    Filters and components

    Filters · Library, the design group and Lane on the library hub, persistent on every tab, plus a Reads, % of an even share range in a MultiQC scope group.

    Section What it holds
    Run at a glance 4 cards, pinned
    Sample sheet Libraries (collapsed, pinned)
    CheckQC verdicts Libraries under the read threshold, Undetermined share against its limit, General statistics
    Read QC after demultiplexing 5 MultiQC panels (Falco and fastp)
    More MultiQC panels 9 MultiQC panels (collapsed)
    Lane table Lane summary (collapsed, pinned to the bottom)

    Did the instrument deliver, per lane, per read and per cycle?

    Cards report clusters passing filter, the lowest lane's pass-filter rate and mean quality, and the weakest read's Q30. A scatter places each lane by Undetermined share and base quality, a profile draws base quality per cycle, and a dot plot crosses lanes with reads. Selecting a lane on the lane table or the scatter narrows the tiles linked to it.

    Filters and components

    Filters · Read and a Cycle range in a Read and cycle scope group, on this tab only.

    Section What it holds
    Lane health 4 cards, Lanes by Undetermined share and base quality
    Quality along the run Base quality per cycle, Lane by read quality
    Sequencing Analysis Viewer metrics 4 cards, PhiX error rate per lane and read, Phasing against prephasing

    The SAV section needs an InterOp summary table

    Error rate, phasing and cluster density live in the InterOp binaries, which Depictio does not parse. Run interop_summary --csv=1 <run folder> and drop the output anywhere under the run (any .csv whose name contains interop_summary); without it the section is hidden.

    How evenly were the reads of each lane shared between the libraries?

    An even pool gives even bars. The stacked composition shows what each lane was made of, Undetermined included, and the sunburst nests run, lane and library. The library balance section puts each library's share of the lane beside a scatter of reads against index purity, where a library with many imperfect index matches stands out; points and table rows select their library.

    Filters and components

    Filters · Share of the lane (%) and Perfect index match (%) ranges in a Balance scope group, on this tab only.

    Section What it holds
    Balance at a glance 4 cards
    Lane composition Libraries per lane, Run, lane, library
    Library balance Share of the lane per library, Reads against index purity
    Per-lane library counts Reads per library and lane (collapsed)

    Is the Undetermined share an index swap, a missing library or a wrong sample sheet?

    Every unassigned index pair is split into its i7 and i5 and checked against the libraries of the same lane. Both indexes in use is the index-hopping or swap signature; Only i7 or Only i5 in use often points to a mistyped index; Neither index in use to a library missing from the sheet or a contamination; Poly-G or N index to a failed index read. The bar chart ranks the top unknown barcodes by share of the lane, coloured by that class.

    Filters and components

    Filters · Barcode class and a Rank in its lane range in a Barcode scope group, on this tab only.

    Section What it holds
    Undetermined at a glance 4 cards
    Top unknown barcodes Unknown barcodes by share of the lane
    Barcode and verdict tables Unknown barcodes, CheckQC findings (collapsed)

    Which library looks different from its group once demultiplexed?

    Cards summarise the fastp read QC of every library and lane. A scatter of duplication against base quality sits beside a linked Library card, which folds to a slim rail until a point is lassoed and then shows that library in full. The group comparison sets the design groups against each other metric by metric, which needs a METADATA_FILE to say anything.

    Filters and components

    Filters · Duplication (%) and GC content (%) ranges in a Library QC scope group, on this tab only.

    Section What it holds
    Library QC at a glance 4 cards
    Library QC distributions Duplication against base quality, Library card, Design groups compared metric by metric
    fastp table fastp read QC (collapsed)

    Tables and point views select on their entity column: the lane table and the lane health and phasing scatters on lane_label; the sample sheet, the per-lane library table, the index purity and library QC scatters and the fastp table on sample; the unknown barcode table on barcode. A pick narrows the other tiles of its collection and follows the project links to the collections they reach. The per-cycle quality profile and the CheckQC verdict table do not select: their collections have no outgoing link.

    Running the pipeline¶

    Depictio reads the output of nf-core/demultiplex, it does not run the pipeline. Run the pipeline first:

    nextflow run nf-core/demultiplex -r 1.8.0 \
  --input samplesheet.csv \
  --demultiplexer bcl2fastq \
  --outdir results -profile docker

    Then point Depictio at the results, adding --var IS_BCLCONVERT=true for a --demultiplexer bclconvert run:

    depictio ingest results/ --template nf-core/demultiplex/latest

    See nf-co.re/demultiplex/usage for full pipeline documentation.

    Required data structure¶

    Point depictio ingest at the directory of one pipeline run. Depictio scans recursively and matches on file name, so the flowcell and lane folder names can differ from the tree below.

    <DATA_ROOT>/
├── <flowcell>/
│   ├── L<lane>/
│   │   ├── Stats/Stats.json                   # bcl2fastq statistics (default route)
│   │   ├── Reports/                           # or BCL Convert: Demultiplex_Stats.csv, Quality_Metrics.csv,
│   │   │                                      #   Top_Unknown_Barcodes.csv (IS_BCLCONVERT)
│   │   ├── checkqc_report.json                # CheckQC verdicts (optional)
│   │   └── *.fastp.json                       # fastp read QC, one per library (optional)
│   └── *interop_summary*.csv                  # optional, from interop_summary --csv=1
├── multiqc/multiqc_data/
│   └── multiqc.parquet                        # bcl2fastq, CheckQC, fastp, Falco
└── pipeline_info/
    ├── params_*.json
    └── *software*versions*.yml

    METADATA_FILE is optional and can live anywhere: a TSV whose first column is the library name, every other column a design factor. GROUP_COL picks the one the tiles group by, the first annotation column otherwise.

    Validation runs¶

    The template was validated against the AWS megatest of the 1.8.0 release (results-daade37c4a75a4c1709ccf12434deb3424141319, test_full profile: one MiSeq flowcell, one lane, paired-end dual-index, demultiplexed with bcl2fastq), and the screenshots above come from it, with the vendored input/library_metadata.tsv grouping the libraries by organism. That run is a useful stress case: several libraries got almost no reads and a large share of the lane went to Undetermined, mostly swapped combinations of indexes in use. The BCL Convert route and the SAV section were checked on MultiQC test-data reports only. megatest.yaml lists the tables-only subset the template needs:

    bash depictio/projects/nf-core/demultiplex/1.8.0/download_test_data.sh /tmp/demultiplex_test
depictio ingest /tmp/demultiplex_test --template nf-core/demultiplex/latest \
  --var METADATA_FILE=depictio/projects/nf-core/demultiplex/1.8.0/input/library_metadata.tsv

    Do not pass --project when ingesting: the dashboard is attached to the project by name, so renaming it breaks a later depictio dashboard import. Re-ingesting accumulates dashboards, so delete the project before repeating a run.
